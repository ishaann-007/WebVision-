# PMAY-U Website Context

## Purpose

This directory is a static capture of the PMAY-Urban government portal homepage, apparently saved from `https://pmay-urban.gov.in/`. It is not a conventional source repository: most of the HTML is a downloaded page snapshot and many local assets are third-party bundles or browser-captured responses.

The primary page is:

- `PMAY (U).html`

The asset directory is:

- `PMAY (U)_files/`

There is no package manifest, build configuration, application source tree, or test suite in this directory.

## Main Page Structure

`PMAY (U).html` contains the complete page markup and inline styles/scripts. The major areas are:

1. Government utility strip
   - Government branding area with login, language translation, and accessibility controls.
   - Uses Font Awesome icons and the Bhashini translation widget.
2. Header branding row
   - Ministry logo: `minister-of-housing-logo.png`.
   - Google custom search markup.
   - PMAY and Swachh Bharat logos.
3. Main navigation
   - Bootstrap/Bootsnav navigation with Home, PMAY(Urban), Progress, and other portal sections.
   - Most links point back to live `https://pmay-urban.gov.in/...` routes or uploaded PDFs.
4. Homepage content
   - The page includes the captured portal sections, sliders, reports, cards, charts, progress information, notices, publications, and social content.
   - Some sections are populated dynamically by API calls or embedded widgets.
5. Footer and supporting portal content
   - Includes government links, site maps, contact/support content, and external services.

The HTML is very large and contains duplicated/legacy markup, inline CSS, commented-out sections, and content generated by browser extensions or third-party widgets. Search by IDs/classes rather than reading the file linearly.

## Local Stylesheets

Stylesheets are loaded from `PMAY (U)_files/` and are generally applied in this order:

- `bootstrap.min.css` and `bootstrap(1).min.css`: Bootstrap layout/components. Two Bootstrap copies are present; changing one may not affect the final cascade as expected.
- `vendor.bundle.base.css`: vendor utility styles, including Perfect Scrollbar.
- `vendor.bundle.addons.css`: additional vendor/plugin styles.
- `responsive.css`: responsive overrides.
- `style.css`: broad portal theme and base styles. It imports several paths such as `../css/...` that are not present in this directory, so those imports may fail when opened locally.
- `Newcustome-1.css`: newer PMAY-specific styles, including the hero/dashboard/stat-card styles and responsive rules.
- `Newcustome.css`: header, navbar, sidebar, and custom layout styles.
- `home.css`: homepage sections, service cards, progress area, sliders, and portal-specific styling.
- `all.min.css`: Font Awesome 6.5.2 icon definitions and font-face declarations.
- `responsive.css`: breakpoint-specific layout rules.
- `website_translation_utility.css` and `website_translation_utility(1).css`: Bhashini translation widget styles.

The visual language is primarily white with PMAY pink/maroon accents such as `#A32966`, `#C94F91`, and `#DB70A6`, plus Bootstrap defaults and several legacy blue/teal sections.

## Local JavaScript and Runtime Behavior

### Portal behavior

`PMAY (U)_files/script-english.js` is the main jQuery initialization script. It:

- Adds the CSRF token to AJAX requests.
- Fetches homepage fragments from `APP_URL` endpoints when matching containers exist:
  - `/api/en/processes`
  - `/api/en/beneficiaries`
  - `/getpartnerslider`
  - `/angikaarapi`
- Initializes Bootstrap carousel behavior for `#home-slider`.
- Initializes LightSlider galleries, PWSTabs, Fancybox, Magnific Popup, Isotope masonry layouts, and other optional plugins when their target elements exist.
- Assumes global variables and plugins from the original hosted application, especially `APP_URL`, jQuery, Bootstrap, and vendor plugins.

`PMAY (U)_files/english.js` is a compiled application bundle. It includes Axios, React, and several compiled components that render dynamic homepage areas when their mount elements exist, including:

- `#angikaar-wrapp`: loads `/api/en/states` and renders state links/cards.
- `#banner-wrapp`: loads `/api/en/sliders` and renders the homepage carousel.
- `#publication-wrapp`: loads `/api/en/publications` and renders publication links.

These components expect `APP_URL` and a compatible backend API. They will not be fully functional when the page is opened as an isolated local file unless the original host/API is available and browser security permits the requests.

### Translation and accessibility

- `website_translation_utility.js` and `bhasni.js` are Bhashini translation plugin copies.
- The HTML also injects the hosted Bhashini script from `https://translation-plugin.bhashini.co.in/v3/website_translation_utility.js` on `DOMContentLoaded`.
- The language dropdown supports many Indian languages and can call Bhashini backend endpoints.
- Accessibility controls are marked by IDs such as `a11yTrigger`, `a11yPanel`, `btnHighContrast`, `btnNormalContrast`, `highlightLinks`, `invert`, `saturation`, `addletterspacing`, `addlineheight`, `hideimage`, `big_cursor`, and `skip_content`.
- The accessibility implementation is partly inline/third-party and should be tested in a browser before changing selectors or classes.

### Search, analytics, and social embeds

- Google Custom Search markup and scripts are embedded in the HTML.
- Google Analytics/Tag Manager code is captured in `js` and inline scripts.
- `widgets.js`, `timeline.9ee124fd8db0c3ba3796e9613bbc9e53.js`, and `pmayurban.html` belong to an X/Twitter timeline embed. `pmayurban.html` currently contains a saved `Rate limit exceeded` response, so the timeline may not render from the snapshot.
- `sdk.js` is a captured Facebook SDK loader.
- `page.html` is a saved Chrome error page for a Facebook subframe, not application source.
- `overlay.js`, `saved_resource`, `f.txt`, and several `cse_*`/`default*` files are captured third-party/browser resources rather than maintainable application modules.

## Important Runtime Assumptions

1. The original page was served from a web origin, not opened directly with `file://`.
2. `APP_URL` is defined by the original server-rendered application.
3. The original PMAY backend routes and APIs are reachable.
4. External services such as Google Search, Google Analytics, Bhashini, Facebook, and X/Twitter are available.
5. Relative asset paths resolve against the page location exactly as captured.
6. Browser behavior, third-party cookies, CORS, CSP, and rate limits may change what works locally.

For a faithful local preview, serve the directory over HTTP rather than opening the HTML directly. Even then, backend-driven sections and external embeds may remain unavailable.

## Maintenance Guidance for Agents

- Treat `PMAY (U).html` as the page entry point and `PMAY (U)_files/` as a captured dependency bundle.
- Before changing behavior, locate the owning ID/class and check whether it is controlled by inline HTML, `script-english.js`, `english.js`, a vendor plugin, or a remote service.
- Prefer small, local changes. Do not reformat the full HTML or minified vendor files.
- Avoid editing third-party/minified files unless the task specifically targets that dependency.
- Be careful with duplicate Bootstrap files and duplicate translation widget markup; CSS/JS cascade order matters.
- Preserve external URLs unless the task explicitly asks for an offline conversion.
- When adding new local behavior, use a clearly named custom stylesheet/script rather than burying more code inside the captured HTML.
- Validate changes in a browser at desktop and mobile widths. A static syntax check is not enough because many failures are missing globals, missing remote APIs, or CSS cascade issues.

## Known Caveats

- The snapshot includes sensitive-looking captured values such as a CSRF token and analytics identifiers. Treat this directory as captured production material and do not expose or reuse those values in a new deployment.
- Some local CSS imports reference files outside `PMAY (U)_files/` and may be broken.
- Several assets are duplicates or stale versions from different capture times.
- Dynamic content can be blank when the API is unavailable.
- The Twitter timeline capture is rate-limited.
- The HTML contains legacy/dead/commented code and generated browser-extension markup; not every included asset is used by the visible page.
- There is no automated test or build command documented for this directory.
